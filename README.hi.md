# dashcam

**आपके AI एजेंटों के लिए डैशकैम।**

रात के 2 बजे हैं, आपका एजेंट क्रैश हो गया। *कौन सा* कॉल फेल हुआ? उसने *वास्तव में* क्या भेजा? पूरे रन की लागत कितनी आई और टोकन कहाँ गए?

गाड़ी का डैशकैम बैकग्राउंड में चुपचाप सब कुछ रिकॉर्ड करता है — और जब कुछ गड़बड़ होती है, तो आप रिकॉर्डिंग रीवाइंड करके ठीक से देखते हैं कि क्या हुआ। **dashcam LLM ऐप्स के लिए यही करता है**: यह आपके प्रोग्राम के हर LLM कॉल को चुपचाप रिकॉर्ड करता है, और फिर आपको एक लोकल टाइमलाइन देता है जिससे आप रीप्ले कर सकें, जाँच सकें और फेलियर का कारण पा सकें।

## dashcam क्यों

| | dashcam | LangSmith / Langfuse | print() डीबगिंग |
|---|---|---|---|
| ज़रूरी कोड बदलाव | **कोई नहीं** | SDK / डेकोरेटर | हर जगह |
| आपकी मशीन से बाहर जाने वाला डेटा | **कभी नहीं** | क्लाउड या सेल्फ-होस्टेड सर्वर | - |
| डिपेंडेंसीज़ | **ज़ीरो** (शुद्ध स्टैंडर्ड लाइब्रेरी) | सर्वर + DB + SDK | - |
| सेटअप समय | 10 सेकंड | मिनटों से घंटों तक | - |
| कॉस्ट ट्रैकिंग | बिल्ट-इन | अलग-अलग | मैनुअल |
| किसी भी फ्रेमवर्क के साथ काम करता है | हाँ (SDK को पैच करता है) | फ्रेमवर्क-स्पेसिफिक | - |

## त्वरित शुरुआत

```bash
pip install dashcam
dashcam demo        # डेमो ट्रेसेज़ बनाता है, API की ज़रूरत नहीं
dashcam             # http://127.0.0.1:8377 पर डैशबोर्ड खोलता है
```

### विकल्प A — ज़ीरो कोड बदलाव (अनुशंसित)

```bash
dashcam install                          # एक बार, .pth हुक लिखता है
DASHCAM=1 python your_agent.py           # बस इतना। सब रिकॉर्ड होता है
```

Windows पर: `set DASHCAM=1 && python your_agent.py`

### विकल्प B — एक लाइन का import

```python
import dashcam
dashcam.instrument()   # मौजूदा openai / anthropic / litellm / mcp को पैच करता है
```

### विकल्प C — स्पष्ट ट्रेस सीमाएँ (वैकल्पिक)

```python
with dashcam.trace("refund-processing-agent") as tid:
    run_agent()   # इसके अंदर के सभी LLM कॉल एक ही ट्रेस में समूहबद्ध होते हैं
```

स्पष्ट सीमाओं के बिना भी, कॉल अपने आप थ्रेड + एक्टिविटी गैप से ग्रुप हो जाते हैं — कोई कोड बदलाव ज़रूरी नहीं।

## आपको क्या मिलता है

<p align="center">
  <img src="docs/screenshot.png" alt="dashcam डैशबोर्ड: एक एजेंट की टाइमलाइन" width="860">
</p>

- **टाइमलाइन रीप्ले** — हर LLM कॉल क्रम में, पूरे रिक्वेस्ट मैसेज, पैरामीटर, टूल्स और रिस्पॉन्स के साथ। किसी भी स्टेप पर क्लिक करके खोलें।
- **अनुमानित टूल स्टेप्स** — dashcam लगातार मैसेज ऐरे की तुलना करके यह पता लगाता है कि कॉल्स के *बीच* में आपके एजेंट ने क्या किया (टूल एग्ज़ीक्यूशन, यूज़र टर्न) — **बिना किसी फ्रेमवर्क इंटीग्रेशन के**।
- **फेलियर एट्रिब्यूशन** — फेल हुए कॉल्स पूरी एक्सेप्शन के साथ लाल कार्ड पाते हैं। ट्रेस लिस्ट में एरर एक नज़र में दिखते हैं।
- **कॉस्ट और टोकन हिसाब** — हर कॉल और हर ट्रेस के लिए टोकन गिनती और USD कॉस्ट अनुमान — OpenAI / Anthropic / DeepSeek / Gemini / Qwen के सामान्य मॉडलों के लिए। `DASHCAM_PRICES` से अपनी कीमत तालिका दें।
- **स्ट्रीमिंग सपोर्ट** — स्ट्रीम किए गए रिस्पॉन्स दोबारा जुड़कर रिकॉर्ड होते हैं, टूल-कॉल फ्रैगमेंट सहित।
- **लोकल और प्राइवेट** — सब कुछ एक ही SQLite फ़ाइल (`~/.dashcam/traces.db`) में। कोई सर्वर नहीं, कोई अकाउंट नहीं, कोई टेलीमेट्री नहीं।

## यह कैसे काम करता है

```
                    आपका प्रोग्राम
                         │
        openai / anthropic / litellm / mcp SDK कॉल
                         │
              ┌──────────▼──────────┐
              │  dashcam patcher   │   SDK एंट्री पॉइंट्स को monkey-patch
              │  (ज़ीरो कॉन्फ़िग)     │   रिक्वेस्ट / रिस्पॉन्स / usage रिकॉर्ड
              └──────────┬──────────┘
                         │
              ┌──────────▼──────────┐
              │  SQLite स्टोर        │   ~/.dashcam/traces.db (WAL)
              └──────────┬──────────┘
                         │
              ┌──────────▼──────────┐
              │  लोकल डैशबोर्ड       │   stdlib का http.server, पोर्ट 8377
              │  रीप्ले · कॉस्ट      │   ट्रेस लिस्ट, टाइमलाइन, JSON एक्सपोर्ट
              └─────────────────────┘
```

dashcam इंपोर्ट के समय इंस्टॉल किए SDK क्लाइंट क्लासेज़ को पैच करता है। आपके प्रोग्राम का व्यवहार बिल्कुल नहीं बदलता — अगर dashcam खुद फेल भी हो जाए, तो चुपचाप फेल होता है और आपका एजेंट चलता रहता है।

### सपोर्टेड SDK

| SDK | एंट्री पॉइंट्स | सिंक | एसिंक | स्ट्रीमिंग |
|---|---|---|---|---|
| openai >= 1.0 | `chat.completions.create`, `responses.create` | ✅ | ✅ | ✅ |
| anthropic | `messages.create`, `messages.stream` | ✅ | ✅ | ✅ |
| litellm | `completion`, `acompletion` | ✅ | ✅ | ✅ |
| mcp >= 1.0 | `ClientSession.call_tool`, `list_tools`, `read_resource` | — | ✅ | — |

इनके ज़रिए जाने वाली हर चीज़ (LangChain, AutoGen, CrewAI, litellm से रूट हुए OpenAI-कंपैटिबल एंडपॉइंट, ...) अपने आप कैप्चर हो जाती है।

## ⚙️ कॉन्फ़िगरेशन

| एनवायरनमेंट वेरिएबल | डिफ़ॉल्ट | मतलब |
|---|---|---|
| `DASHCAM` | सेट नहीं | `1` सेट करने पर `.pth` हुक इंटरप्रेटर स्टार्टअप पर ऑटो-इंस्ट्रूमेंट करता है |
| `DASHCAM_DB` | `~/.dashcam/traces.db` | SQLite डेटाबेस की जगह |
| `DASHCAM_PRICES` | बिल्ट-इन तालिका | JSON कीमत तालिका का पाथ: `{"मॉडल-सबस्ट्रिंग": [इनपुट_प्रति_मिलियन_टोकन, आउटपुट_प्रति_मिलियन_टोकन]}` |

कीमत मैचिंग सबस्ट्रिंग आधारित है, सबसे लंबा की जीतता है (जैसे `gpt-4o-mini`, `gpt-4o` से आगे)। कीमतें अनुमानित हैं — बिलिंग-ग्रेड सटीकता के लिए अपनी तालिका से ओवरराइड करें।

## FAQ

**क्या यह मेरे एजेंट को धीमा करेगा?**
रिकॉर्डिंग = हर LLM कॉल पर एक SQLite इंसर्ट (माइक्रोसेकंड)। आपके LLM कॉल्स सैकड़ों मिलीसेकंड लेते हैं। आपको कुछ महसूस नहीं होगा।

**अगर dashcam खुद टूट गया तो?**
dashcam की पूरी इंटरनल लॉजिक डिफेंसिव तरीके से रैप की गई है — dashcam के अंदर कुछ भी एक्सेप्शन उठे तो वह दबा दी जाती है और आपका प्रोग्राम बिना असर के चलता रहता है।

**क्या डेटा कहीं भेजा जाता है?**
नहीं। कोई नेटवर्क कॉल नहीं, टेलीमेट्री नहीं, अकाउंट नहीं। डैशबोर्ड सिर्फ़ 127.0.0.1 पर बाइंड होता है।

**कॉल ट्रेस में कैसे ग्रुप होते हैं?**
स्पष्ट रूप से `dashcam.trace(name)` से, या अपने आप: एक ही थ्रेड के 5 मिनट की एक्टिविटी गैप वाले कॉल एक ही ट्रेस में जाते हैं। निष्क्रिय ट्रेस अपने आप बंद हो जाते हैं।

**स्ट्रीमिंग रिस्पॉन्स?**
चंक्स (टेक्स्ट, टूल-कॉल फ्रैगमेंट, usage) जमा होते हैं और स्ट्रीम खत्म होने पर रिकॉर्ड होते हैं। OpenAI का `stream_options={"include_usage": True}` usage कैप्चर के लिए सम्मानित होता है।
